# Staff, GameMaster, and donor capability migration matrix

This is the maintained action-level migration ledger for Issues [#3](https://github.com/itschase/OwlMTA-2026/issues/3) and [#14](https://github.com/itschase/OwlMTA-2026/issues/14). It turns broad legacy rank predicates into reviewable actions without treating a Discord role, donor tier, organization rank, duty flag, or MTA ACL as interchangeable authority.

All entries are source-reviewed unless a row explicitly says `fixed-in-source`. MTA, Discord, the identity adapter/service, role resolution, database state, and gameplay remain runtime-unverified.

## Decision model

Every protected action is evaluated as separate gates:

1. **Authenticated actor** — server-owned Owl account session and, for remote events, MTA `client` binding.
2. **Global grant** — a narrow named capability resolved through the server-only `account:hasDiscordCapability` facade when the action reaches cutover.
3. **Local policy** — duty, hierarchy, target type, target immunity, ownership, organization membership/rank, proximity, world, current state, and value bounds as applicable.
4. **Audit and lifecycle** — bounded diagnostic/audit outcome, current grant freshness, logout/revocation handling, and no stale callback restoring access.

Shadow mode compares the legacy decision with the Discord-backed result but returns only the reviewed legacy decision. A shadow grant never authorizes an action. Missing, stale, mismatched, or unavailable capability state is recorded, not converted into access. Donor/supporter entitlement is excluded from moderation even during shadow migration.

## First shadow implementation: player freeze

`admin-system/capability_shadow_s.lua` now queries the existing server-only Owl facade for the action's named capability (currently `moderation.player.freeze` and `moderation.player.nudge`) and emits rate-limited, bounded `[AUTH][CAPABILITY_SHADOW]` fields: action, capability, legacy result, Discord result, resolver state, comparison, and `enforcement=legacy`. The account resource uses the same bounded fields for its internal application-bypass comparison and distinguishes invalid session/input, unavailable adapter, adapter error, and resolved deny without exposing identity data. The administrative helper checks the optional account resource with MTA's [getResourceState](https://wiki.multitheftauto.com/wiki/GetResourceState) and uses the exported-function [call](https://wiki.multitheftauto.com/wiki/Call) boundary only when that resource is running. Neither path receives or records a Discord user ID, role ID, role list, token, or credential. The administrative helper attempts a durable actor-bound mismatch/unavailable record; the application gate attempts its actor-bound action audit only after persistence and session readback. Logger failure receives a credential-free outcome and cannot change enforcement.

`/freeze`, `/unfreeze`, `/nudge`, and the post-admission application bypass enforce only the retained Trial Admin predicate in this phase. Donor `supporter_level` no longer authorizes these actions. Capability results are comparison evidence only, so a Discord grant cannot bypass the legacy gate, target/session validation, persistence, cooldown, or action logging. The application bypass denies character selection if the repository's checked legacy query wrapper reports failure or synchronized session state cannot be read back, and attempts an actor-bound audit after both succeed. Native MTA [dbExec](https://wiki.multitheftauto.com/wiki/DbExec) was not used as a success proof because its boolean only rejects an incorrect connection. Nudge uses the explicit receiver and checked return contract of MTA's [triggerClientEvent](https://wiki.multitheftauto.com/wiki/TriggerClientEvent), rejects non-active targets, applies a one-per-five-second successful-delivery limit that accounts for documented [getTickCount](https://wiki.multitheftauto.com/wiki/GetTickCount) wraparound, reports delivery failure, attempts a successful actor/target audit, and no longer exposes the local `playthenoise` developer command. The unused remotely callable `remoteFreezePlayer` event was removed after repository-wide search found no client or server caller; the staff commands remain available.

Before capability cutover, a disposable environment must cover legacy allow/capability allow, legacy allow/capability deny, legacy deny/capability allow, both deny, adapter unavailable/error/stale, role loss during a session, logout/reconnect, target disconnect, vehicle/ped/restraint states, command burst behavior, and audit/logger failure. Operators must review mismatches and explicitly decide duty and hierarchy policy. No role ID is supplied by OwlMTA; installation-specific mappings remain blank in the reusable identity service.

## Next bounded conversions

1. Audit application override persistence, live/offline target selection, database outcomes, and notification/audit behavior before removing donor fallthrough and adding the non-granting `moderation.application.override` comparison.
2. Reconcile GameMaster persistence, missing exports, report-duty semantics, and the supporter-named UI fields before introducing `gamemaster.reports.handle`.
3. Split inspection, roster, rank mutation, specialty tools, and operator controls into narrow actions. Never bulk-replace `isPlayerStaff()`, numeric ranks, organization permissions, or MTA ACL with a single capability.
