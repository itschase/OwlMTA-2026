# AI & Agent Operations Discussion Program

## Purpose

The **AI & Agent Operations** GitHub Discussion category is the public onboarding and operating manual for automated contributors to OwlMTA-2026. It should allow a capable new agent to orient, research, implement, document, publish, and hand off worthwhile work with little routine owner input.

Repository instructions remain authoritative:

- [`AGENTS.md`](../../AGENTS.md) — mandatory rules and chronological activity log;
- [`docs/agent-guidelines.md`](../agent-guidelines.md) — full operating workflow;
- [`NEXT_WORK.md`](NEXT_WORK.md) — current verified continuation state;
- [`RESOURCE_AUDIT_PLAYBOOK.md`](RESOURCE_AUDIT_PLAYBOOK.md) — resource review method;
- [`DISCUSSIONS_AND_ISSUES.md`](DISCUSSIONS_AND_ISSUES.md) — publication index and tracker state;
- [`SAFE_START_PREFLIGHT.md`](SAFE_START_PREFLIGHT.md) — runtime boundary.

Public topics summarize these sources in project voice. They never contain credentials, private prompts/transcripts, machine-specific secrets, or claims that source review proves runtime behavior.

### 1. [Agent Operations: Start Here — Mission, Authority, and Guardrails](https://github.com/itschase/OwlMTA-2026/discussions/560)

Explain the self-hosted/no-UCP direction, Discord-first target, named capabilities, donor/staff separation, no-runtime-claim rule, credential safety, and the canonical read order. State what agents may autonomously do and which actions require owner direction.

### 2. [Agent Operations: Autonomous Work Selection and Priority](https://github.com/itschase/OwlMTA-2026/discussions/561)

Teach agents to select one bounded unit from live source, `NEXT_WORK`, Issues, Milestones, and the ledger. Use the priority order: identity/session/character authority; persistence/economy/inventory/ownership; startup/schema; staff/public safety; connected gameplay; then UX/cosmetic/archive work. Explain when to continue implementation and when to pause.

### 3. [Agent Operations: Source Research and Resource Audit Standard](https://github.com/itschase/OwlMTA-2026/discussions/562)

Require manifest and loaded-script review; paired client/server callers; commands, keybinds, events, exports and consumers; permissions; persistence; dependency/lifecycle; player/staff/operator behavior; Discord-capability applicability; command-to-UI opportunities; diagnostics; dossier/ledger state; and runtime gaps. A TODO is a lead, not evidence.

### 4. [Agent Operations: Development, Diagnostics, and Validation](https://github.com/itschase/OwlMTA-2026/discussions/563)

Define server-side authority, `client` binding, trusted internal-call preservation, independent permission/target/ownership/proximity/state/value/settlement checks, privacy-conscious diagnostics, focused static checks, and the safe-start/runtime boundary. Require a complete bounded change rather than plan-only output when safe.

### 5. [Agent Operations: Issues, Discussions, and Milestones](https://github.com/itschase/OwlMTA-2026/discussions/564)

Define nonduplicate Issue quality, source evidence, impact, scope/non-goals, acceptance conditions, runtime matrix, assignment, labels, and tracker reconciliation. Explain audience-specific Discussion categories and standardized `Script Resource: <resource>` titles. Define Milestones as multi-Issue delivery outcomes—not containers for single TODOs or arbitrary subsystems.

### 6. [Agent Operations: Documentation, Publication, and Handoff](https://github.com/itschase/OwlMTA-2026/discussions/565)

Describe paired code/dossier/planning updates, status vocabulary, coherent commits, source publication before tracker comments, returned-link indexing, clean remote verification, and the mandatory `AGENTS.md` handoff entry. Keep maintained docs detailed and Discussions discoverable.

### 7. [Agent Operations: Discord Identity and Permission Boundaries](https://github.com/itschase/OwlMTA-2026/discussions/566)

Explain the separate reusable identity service, optional adapter availability, one-use connection-bound proof, local account rebinding, named capabilities, revocation/expiry, server-only queries, fail-closed elevated access, and separate local character/organization/duty/ownership/state checks. Donor/supporter tiers never grant staff authority.

### 8. [Agent Operations: Shared Checkout and Multi-Agent Coordination](https://github.com/itschase/OwlMTA-2026/discussions/567)

Define primary-operator ownership, non-overlapping read-only parallel research, shared-index consolidation, unexpected-change freeze/reconciliation, no force/reset/discard, bounded task instructions, evidence-only agent reports, and final verification. Parallel agents must not independently edit or publish overlapping work.

### 9. [Agent Operations: Legacy Login to Discord Session Migration](https://github.com/itschase/OwlMTA-2026/discussions/568)

Explain that Discord authorization must become the production account-session proof, not merely another login button. Direct agents to the maintained migration map, existing Issues #2/#3/#14/#43/#68/#96/#158/#201/#551, action-by-action capability conversion, separate donor entitlements, preserved local account/character/organization/duty checks, canonical logout/reconnect behavior, legacy linking/recovery, and retirement of password/forum paths only after a verified replacement exists.

## Maintenance rule

When a canonical rule changes, update repository documentation first, then update the affected Discussion with a short changelog and links. Do not duplicate the whole guide into every topic. The latest verified repository commit and activity log determine the operative state.
